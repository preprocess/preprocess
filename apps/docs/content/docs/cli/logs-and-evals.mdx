`preprocess logs` and `preprocess evals` give you terminal-first observability
and regression testing against real production cases without clicking through
the dashboard.

## Streaming run logs

`logs` prints structured run logs, newest first, scoped to a single case, an
agent, a deployment, or the entire organization:

```sh
npx preprocess logs --case <case id> --level error
```

- **Filtering.** Narrow output by `--case`, `--agent`, `--deployment`, or
  `--level` when diagnosing a failing tool call, timeout, or schema error.
- **Permissions.** Reading logs for a specific agent requires access to that
  agent; organization-wide log queries require membership in Developers or an
  Admin/Owner role (an organization API key has Admin rights).
- **Secret redaction.** Bound secret values never enter run logs.

## Running eval suites

Every completed case with human corrections can join an agent's eval suite.
`evals run` replays a suite against a deployment (production by default, or any
preview deployment id) once per `--model` flag and waits for the full results:

```sh
npx preprocess evals list
npx preprocess evals run regressions --model deepseek-v4.1-flash --model kimi-k3.1-pro
```

During an eval replay, Preprocess guarantees deterministic, side-effect-safe
execution:

- tools marked `sideEffects: true` reuse their recorded outputs instead of
  calling external systems again;
- sandbox calls reuse captured outputs without booting containers;
- `search_cases` sees only cases completed _before_ the replayed case started,
  preventing future-data leakage.

Suites marked `runOnPush` also run on their own against each new production
deployment when the agent's `evals: {onPush}` is on; see
[Evals](/concepts/evals). Trigger any suite on demand with
`preprocess evals run` from your terminal or CI.
