---
title: Secrets
description:
  Declare organization secrets your agent needs, bound only into your Dynamic
  Worker and never exposed to the model.
---

`secrets` declares the names of organization secrets your agent code reads from
`ctx.env`. Secret values are stored envelope-encrypted per organization in
Postgres and injected into your Dynamic Worker's `env` only if an Owner or Admin
has explicitly granted that secret to the agent.

## Why secrets are declared in code and granted in the app

Separating declaration (in code) from granting (in organization guardrails)
prevents an unreviewed branch or new agent from silently accessing production
credentials. When you deploy code that adds a secret name the agent has not been
granted yet, the deployment does not fail—it enters `waiting` and opens a
guardrail request for an Admin. Once granted, live deployments re-evaluate
automatically and become `ready`. See
[Deployments](/concepts/deployments#waiting-deployments-vs-failed-deploys).

## Rules and isolation boundaries

- **Naming.** Secret names must match `^[A-Z][A-Z0-9_]{0,63}$`. Reserved names
  (`MCP`, `MODELS`, and anything starting with `PREPROCESS_`) are rejected at
  deploy time.
- **Type safety.** Listing secret names in `secrets` narrows the keys on
  `ctx.env` to `Readonly<Record<S, string | undefined>>` across every tool in
  that agent.
- **Ungranted secrets.** Any declared secret without an active grant is
  `undefined` at runtime.
- **Model and log isolation.** Secret values enter only your Dynamic Worker's
  `env`. They never enter the model's context, the case thread, run logs, or run
  capture.

```ts
import { agent, tool } from "@preprocess/sdk";
import { z } from "zod";

export default agent({
  instructions: "Fetch customer billing status.",
  secrets: ["BILLING_API_KEY"],
  tools: {
    get_status: tool({
      description: "Read billing status for a customer id",
      input: z.object({ customerId: z.string() }),
      run: async ({ customerId }, { env }) => {
        if (!env.BILLING_API_KEY) {
          throw new Error("BILLING_API_KEY is not bound");
        }
        const res = await fetch(
          `https://billing.example.com/customers/${customerId}`,
          { headers: { authorization: `Bearer ${env.BILLING_API_KEY}` } },
        );
        return res.json();
      },
    }),
  },
});
```

<Callout>
  As a second line of defense, the SDK automatically strips bound secret values
  from tool results, thrown errors, and console output. Code that encodes or
  transforms a secret (for example, base64-encoding it) can still leak it, so
  return only the specific fields the model needs.
</Callout>
