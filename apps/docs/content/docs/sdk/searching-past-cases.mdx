---
title: Searching past cases
description:
  Opt in to the search_cases tool so an agent can look up how similar completed
  cases were resolved.
---

`searchCases: true` gives an agent the built-in `search_cases` platform tool,
allowing the model to search its own completed cases when it encounters an
unfamiliar vendor, edge case, or formatting convention. It is off by default so
agents only read historical cases when you explicitly opt in—either in code or
as a temporary override in the agent's settings.

## Why past-case search is separate from memory

[Memory](/sdk/memory) injects a small set of human-approved rules (up to 100)
into every case. Real operations also have thousands of long-tail precedents
that would never fit in a prompt. `search_cases` lets the model query Postgres
full-text search on demand for words, invoice numbers, or vendor names and see
how operators actually corrected similar cases.

```ts
import { agent } from "@preprocess/sdk";

export default agent({
  instructions: "Extract the invoice fields.",
  searchCases: true,
  tools: {},
});
```

## Scope, results, and eval safety

- **Strict isolation by agent and environment.** Search covers only this agent's
  completed cases in the same organization and environment. Production and
  preview deployments see only their own environment's cases, shared across all
  deployments of the agent.
- **What each match returns.** Every result includes the case's title,
  completion date, input text (truncated to a few thousand characters, plus file
  names), the agent's final message, the final answers as corrected by
  operators, and `changed`—the exact answer paths a person edited.
- **Retention respected.** A case deleted by an Owner or purged by a retention
  policy leaves the search index immediately.
- **Zero leakage during evals.** When an eval suite replays a historical case,
  `search_cases` only returns cases completed _before_ the replayed case started
  (with their answers as they stood then), and never returns the replayed case
  itself or another case with the same input.
- **Full capture.** Every query and its matched results are recorded inside the
  case's run capture.
