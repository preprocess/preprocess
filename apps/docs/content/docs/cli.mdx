`@preprocess/cli` is the command-line bridge between your local git repository
and your Preprocess organization. Use it to bundle and deploy agents from a
laptop or CI, pull dashboard setting overrides and group slugs back into
`preprocess.config.json` before a release, start cases against production or
preview deployments, inspect run logs, run eval suites, and install or upgrade a
self-hosted Preprocess stack in your own Cloudflare account
(`preprocess install`).

Hand this prompt to your coding agent to set up the CLI and deploy.

## Install

```sh
npm install --save-dev @preprocess/cli
```

## Sign in

The CLI reads three environment variables:

<Configured
  lang="sh"
  code={`export PREPROCESS_API_URL={origin}
export PREPROCESS_ORG=org_...
export PREPROCESS_API_KEY=...`}
/>

- `PREPROCESS_API_URL` is the origin your organization's app is served from.
- `PREPROCESS_ORG` is your organization's id.
- `PREPROCESS_API_KEY` is an organization API key. An Owner or Admin creates one
  in Developers → Keys & webhooks. The key acts with Admin rights, so it can
  deploy, promote, and work cases (it cannot approve—approving always requires a
  person). Each key is shown once at creation, and the CLI reads it only from
  the environment so it never lands in shell history or CI logs.

Pass `--api` and `--org` to override the first two for a single command.

## Deploy

```sh
npx preprocess deploy
```

`deploy` bundles `src/index.ts` (or the entry file you specify), uploads the
bundle with your current git branch and commit, and prints the new deployment's
status (`ready` or `waiting`), any cleared overrides, and any build warnings.
The first deploy under a new name creates the agent. Deploying from `main`
creates and promotes a production deployment; deploying from any other branch
(or outside git) creates an isolated preview. Settings in
`preprocess.config.json` beside `package.json` ship with the bundle.

## Keep settings in step

Because code is the truth at deploy, promoting a new release clears any
temporary overrides set in the app dashboard. Run `config pull` before deploying
to pull active overrides into `preprocess.config.json` and commit them to git;
run `groups pull` to write the organization's current group slugs into the same
file so `deploy` can warn when code references a missing slug.

```sh
npx preprocess config pull
npx preprocess groups pull
```

## Logs and evals

```sh
npx preprocess logs --case <case id> --level error
npx preprocess evals list
npx preprocess evals run regressions --model deepseek-v4.1-flash --model kimi-k3.1-pro
```

`logs` streams run logs, newest first, filtered by case, agent, deployment, or
the whole organization (organization-wide logs require Developers or Admins).
`evals run` executes a suite against a deployment (production by default), once
per `--model`, and waits for the results so you can compare accuracy, latency,
and cost across models before changing production.
