  How organization secrets and outbound MCP OAuth tokens are isolated from the
  model and injected at tool dispatch.

Preprocess stores organization secrets and outbound MCP OAuth tokens in
encrypted organization-scoped storage and delivers them only to the agent's
isolated code or to the platform's MCP token service—never to the model, the
case thread or logs.

## Why credentials never enter the model loop

Agent prompts, tool results and case threads are exposed to the model and to
human operators reviewing a case. If API keys or OAuth tokens lived in the
prompt or in agent state, a prompt injection or stray log line could leak them.
Keeping credentials strictly outside the model loop lets agents call external
systems through typed tools without ever seeing the underlying keys.

## Organization secrets

Secrets are write-only values belonging to an organization (up to 5,120
characters each). Secret names must match `/^[A-Z][A-Z0-9_]{0,63}$/` and cannot
use the reserved names `MCP`, `MODELS` or anything starting with `PREPROCESS_`.

- **Encrypted per organization:** Each secret value is encrypted with
  AES-256-GCM using the organization's own data key (`org_keys`), wrapped by the
  platform's master key in Secrets Store, with `organizationId|secretId|version`
  as associated authenticated data. No read endpoint ever returns a secret
  value—`GET /v1/orgs/{org}/secrets` returns only names, versions, update
  timestamps and grant counts.
- **Granted per agent:** Declaring a secret in `secrets: ["ERP_API_KEY"]` in
  agent code is not enough on its own. An Owner or Admin must grant that secret
  to the agent (directly or by approving the deployment's guardrail request).
  Any declared secret without a grant arrives as `undefined` on `ctx.env`.
- **Injected only into Dynamic Workers:** When the case runtime dispatches a
  tool call or schema hook, it loads the deployment's bundle into a Cloudflare
  Dynamic Worker isolate keyed by organization, agent, deployment, secrets
  version and network rules. Rotating or revoking a secret increments its
  version so the next dispatch loads a fresh isolate without needing a redeploy.
- **Redaction as defense in depth:** The SDK automatically strips bound secret
  values (length 4 or longer) from tool results, thrown errors and `console.*`
  output, replacing them with `[redacted:NAME]`. Code that encodes or slices a
  secret before returning it can still leak it, so return only the fields the
  model needs.

## Outbound MCP connections

Agents can call external remote MCP servers over Streamable HTTP (MCP protocol
`2025-06-18`) without managing OAuth flows or holding access tokens. Servers
that only speak the older HTTP+SSE transport work too, as a fallback.

- **Organization-scoped registration and OAuth:** An Owner or Admin registers a
  remote server under a slug with `PUT /v1/orgs/{org}/mcp-servers/{server}`. The
  URL must use `https`. Preprocess probes the URL to detect whether it requires
  OAuth (`401` with `WWW-Authenticate` resource metadata) or accepts
  unauthenticated sessions (`none`). For OAuth servers, Preprocess performs
  dynamic client registration and runs an authorization code + PKCE flow
  (`callback` at `/v1/mcp/oauth/callback`, which sends the browser back to
  Settings → Developers → Integrations in the app). Connections belong to the
  organization—there are no per-user connections—and tokens are encrypted under
  the organization's key.
- **Transport detection:** Registration tries Streamable HTTP first. If the
  server answers that request with `400`, `404` or `405`, Preprocess tries the
  deprecated HTTP+SSE transport: a `GET` opens an event stream whose `endpoint`
  event names where to post messages. The endpoint must be on the same origin as
  the registered URL, or registration fails and nothing is sent there. The
  detected transport is stored and returned as the read-only `transport` field
  (`streamable_http` or `sse`); registering the URL again detects it again, so a
  server that moves to Streamable HTTP is picked up. Every call to a server, on
  either transport, gives up after 60 seconds and closes its connection.
- **Per-agent grants:** Like secrets, an Owner or Admin must grant an MCP server
  to each agent that declares it in `mcp: ["crm"]`.
- **Broker token injection:** At dispatch, the runtime binds an `MCP` capability
  (`McpBroker`) whose props fix the organization, agent and deployment. Agent
  code cannot read or modify those props. When a tool calls
  `ctx.mcp("crm").call(...)` or `ctx.mcp("crm").listTools()`, `McpBroker`
  verifies the deployment declares the server and the agent holds a grant,
  decrypts and refreshes the organization's OAuth token if expired and forwards
  the JSON-RPC call. If a refresh fails, the connection moves to `needs_reauth`
  and writes `mcp_connection.needs_reauth` to the audit log.

## Inbound MCP vs. outbound MCP

This page covers **outbound** MCP servers that your deployed agents call during
a case. If you want an external MCP client such as Claude Code or Cursor to
manage your Preprocess agents, cases, logs and evals, see
[Connect via MCP](/mcp).

## How to use it

Declare the secrets and MCP servers your agent needs, then read them from
`ctx.env` and `ctx.mcp()` inside tool handlers:

```ts
import { agent, tool } from "@preprocess/sdk";
import { z } from "zod";

export default agent({
  instructions: "Sync approved invoices to the ERP and look up CRM accounts.",
  secrets: ["ERP_API_KEY"],
  mcp: ["crm"],
  tools: {
    find_account: tool({
      description: "Search CRM accounts by company name",
      input: z.object({ query: z.string() }),
      run: ({ query }, ctx) =>
        ctx.mcp("crm").call("search_accounts", { query }),
    }),
    post_invoice: tool({
      description: "Send an invoice payload to the ERP",
      input: z.object({ invoiceId: z.string(), total: z.number() }),
      sideEffects: true,
      run: async ({ invoiceId, total }, ctx) => {
        if (!ctx.env.ERP_API_KEY) throw new Error("ERP_API_KEY is not granted");
        const res = await fetch("https://erp.example.com/v1/invoices", {
          method: "POST",
          headers: {
            authorization: `Bearer ${ctx.env.ERP_API_KEY}`,
            "content-type": "application/json",
          },
          body: JSON.stringify({ invoiceId, total }),
        });
        return { status: res.status };
      },
    }),
  },
});
```

See [SDK secrets](/sdk/secrets) and [SDK MCP servers](/sdk/mcp-servers) for
reference details.
